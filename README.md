# 水下考古潜水记录

直接打开 `index.html` 使用（零依赖，无需构建）。顶部两个页签：

- **标记台**（原有视图）：点击沉船平面图添加标记，按类型筛选、标记列表 / 潜次时间线两种视图、编辑、删除、导出 `dive-marks.json`。标记可关联测线；测线修订后，潜次时间线按修订后的潜次顺序分组。
- **测线与浮标回收台**：登记测线号、浮标、两端基线点、布设 / 回收时刻、流速与淤积，登记布设端与回收端坐标。

## 判定规则（`js/judge.js`）

回收后满足任一条件，测线自动转入**待复测**并在卡片列出原因：

1. **两端坐标不一致**：布设端与回收端任一偏差超过 0.5 米；
2. **淤积较布设多两成**：回收淤积 ≥ 布设淤积 × 1.2；
3. **浮标串线**：浮标实际回收所在测线号与登记测线号不一致。

**复测确认**只能对待复测测线发起，必须由与原测绘员不同的另一名测绘员确认，并重设两端基线点 / 坐标。确认后：

- 旧版完整快照进入「旧版留档」（`localStorage` 键 `zfl30LineArchive`），可展开查看；
- 测线版本号 +1，按新基线对关联标记重新排序（`seq`），并生成新的潜次顺序（`orderedDives`），潜次时间线随之重排；
- 重设基线后的新版本等待再次回收。

## 文件划分

| 文件 | 职责 |
| --- | --- |
| `js/judge.js` | 判定业务：状态判定、复测校验、基线投影重排、修订版本构建（纯函数） |
| `js/archive.js` | 存档业务：`localStorage` 读写、旧版留档、JSON 导出 |
| `js/page.js` | 页面业务：两个台的渲染与交互、页签、表单 |

> 三个文件按经典脚本顺序加载（非 ES Module），因此以 `file://` 直接双击打开也可用。

## 导出

- 标记台「导出JSON」：沿用原 `dive-marks.json`，格式不变。
- 回收台「导出测线JSON」：`survey-lines.json`，包含当前各版测线、旧版留档与标记。

数据保存在浏览器 `localStorage`（键 `zfl30Marks`、`zfl30Lines`、`zfl30LineArchive`），首次打开会写入示例数据；清除站点数据后重新打开可恢复示例。
